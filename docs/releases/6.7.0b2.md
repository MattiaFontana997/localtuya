# LocalTuya 6.7.0b2

Beta based on v6.7.0b1. Normal device control remains local.

## Fixes

- Missing cloud IP no longer classifies a direct Wi-Fi device as a gateway child. UUID fallback requires explicit subdevice or parent metadata.
- Gateway children without their own local key remain selectable when a gateway can supply the connection key.
- Missing parent associations require an explicit gateway choice, even when the account has only one hub.
- Gateway selection is applied consistently during initial setup, adding another device, and bulk onboarding. In bulk mode the selected gateway applies only to children; Wi-Fi devices remain direct.
- Child product matching uses the child's product ID instead of the gateway's discovery product key.
- Diagnostics redact gateway keys, addresses and child routing identifiers.
- Unsolicited child updates received during a pending query are retained instead of being overwritten by the request cache.
- The connection timeout now also covers TCP socket establishment, avoiding unbounded waits before the configured timeout starts.
- Keyless subdevices are not misclassified as candidate gateways.
- Connection error text no longer suggests that every protocol or authentication failure means the IP address is wrong.

## Validation and known limits

All 659 regression tests pass with Python 3.14 and Home Assistant 2026.9.0. Six loopback TCP integration tests use an independently implemented Tuya 3.3 peer to verify encrypted thermostat state/target operations, fragmented packets, 100 interleaved operations across five children on one socket, unsolicited update retention and isolation, socket-drop recovery, and bounded connection establishment. These are simulated protocol tests, not tests of the reported physical devices. Release publication requires tests, HACS and Hassfest validation to pass.

These changes reproduce and fix software failures; they do not establish hardware compatibility for the reported thermostat or Bluetooth gateway. Some hubs do not expose all children through the local Tuya protocol. The upstream missing-hub report for category `wfcon` is already covered by this integration's category list.

## Trying this beta

In HACS, enable prerelease versions for this repository and select 6.7.0b2, then restart Home Assistant. Alternatively, extract the attached ZIP over the Home Assistant configuration directory; it contains `custom_components/localtuya`.

Retry adding the thermostat as a direct Wi-Fi device, leaving gateway selection empty. For gateway lamps, select the lamp and its actual gateway. When asked for a child's host, enter the gateway's LAN IP. Multiple lamps on the same hub may be selected together with that hub in bulk setup.

Existing configured devices are not automatically deleted or reclassified. If the thermostat still fails with the corrected routing, capture a fresh debug log of the connection attempt; the exact remaining cause requires that evidence.
